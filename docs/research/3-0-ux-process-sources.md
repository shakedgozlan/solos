## Worker B: flows, prototyping, testing, handoff (Sonnet reader, 2026-11-20)
Network: nngroup.com, designtokens.org, basecamp.com not fetchable; worked from search snippets.

1. Flows with states: one flow per key task; happy path, then empty/loading/error/partial/offline/permission-denied. Wireflows pair nodes with rough screens. NN/g distinguishes flows vs journeys (from memory). AI-written code tends to cover only happy paths, so states are the most valuable output. ~2-4 h for ~6 flows.
2. Low-fi: Shape Up breadboards and fat-marker sketches (places, affordances, connections). Content-first: real Hebrew copy and data first. Google Design warns a polished vibe-coded prototype before core questions are solved is a trap: https://design.google/library/code-is-a-design-material
3. Testing: NN/g 5 users find most problems; 3 rounds of 5 beat 1 of 15: https://nngroup.com/articles/why-you-only-need-to-test-with-5-users/ ; qual studies don't predict frequency: https://www.nngroup.com/articles/5-test-users-qual-quant/ . Prototype-in-code trend: https://plotly.com/blog/plotly-designers-build-beyond-figma-mockups-ai/ , https://www.salesforce.com/blog/designers-coding-agent-how-to/ , https://uxdesign.cc/why-i-skipped-figma-and-prototyped-in-code-instead-8d1dab51c07d , risks: https://smashingmagazine.com/2025/09/intent-prototyping-pure-vibe-coding-enterprise-ux/ . One user = dogfooding, finds daily friction only. Real-device tests matter for mic, RTL keyboard, PWA install, safe areas. Suggest 3-5 friends for one first-click/think-aloud round.
4. Handoff: DTCG tokens stable 2025.10 (2025-10-28), not W3C standards track: https://w3.org/community/design-tokens/2025/10/28/design-tokens-specification-reaches-first-stable-version/ . Figma: Dev Mode snippets come from the file not codebase; Code Connect gives agents import paths; MCP can't guarantee code if the system is messy: https://figma.com/blog/the-benefits-of-code-connect-in-mcp , https://www.figma.com/resource-library/automated-ui-handoff/ . Drift causes: undocumented states, hard-coded values, two sources of truth. For one person + Claude: code + token file are truth, Figma mirrors; Storybook/Code Connect likely overkill; one "all components in all states" page suffices.
5. Interaction: save optimistically with undo; confirm dialogs only for destructive steps (Aza Raskin, https://alistapart.com/article/neveruseawarning ; Jef Raskin, The Humane Interface). Optimistic UI hard part is errors: https://shop.smashingmagazine.com/2016/11/true-lies-of-optimistic-user-interfaces/ . Recognition over recall (Nielsen heuristic). Read-back card: test for habituation; try auto-save + 5 s undo for low-risk captures, compare edit/cancel rates.
Suggested order: flows+states, content/copy, greybox in code, device test, tokens, visual polish.

## Worker C: layout, hierarchy, AI-slop, RTL (Sonnet reader, 2026-11-20)
Network: nngroup, material, mintlify blocked; search summaries.
- Hierarchy = size + weight + colour; de-emphasise labels: https://www.refactoringui.com/previews/labels-are-a-last-resort . One primary per screen, max 3 text styles per card; small type scale, 2 weights; 4pt base / 8pt rhythm (Assumption).
- RTL readers use a mirrored F-pattern: https://www.nngroup.com/alertbox/reading_pattern.html . Anchor top-right.
- Thumb: ~75% thumb-driven (Hoober via https://www.smashingmagazine.com/2016/09/the-thumb-zone-designing-for-mobile-users ); counterpoint https://addyosmani.com/blog/touch-friendly-design/ ; max 5 bottom destinations: https://smashingmagazine.com/2016/11/the-golden-rules-of-mobile-navigation-design
- Few: dashboard = single screen, at a glance; largest = most important; cut the rest: https://uxmatters.com/mt/archives/2007/04/book-review-information-dashboard-design.php . Apple widgets: glanceable, relevant, one message: https://developer.apple.com/design/human-interface-guidelines/widgets . Tile readable in ~2 s.
- AI slop tells and fixes: https://github.com/Laith0003/ux-skill/wiki/Anti-AI-slop-ban-list , https://world.hey.com/kostac/spot-the-slop-a-ui-designer-s-guide-to-fixing-ai-defaults-4c448c9c , https://uxdesign.cc/ai-design-isnt-ugly-it-s-fluent-and-that-s-the-problem-131b2f4eb78c , https://dev.to/jaainil/ai-purple-problem-make-your-ui-unmistakable-3ono . Problem is fluent averageness. Fixes: one deliberate hue, distinctive Hebrew-capable fonts, varied tile sizes by importance, one icon set, real copy, one signature element, design brief + do-not list, design states first.
- RTL: https://m1.material.io/usability/bidirectionality.html , https://doc.wikimedia.org/codex/latest/style-guide/bidirectionality.html , https://developer.apple.com/design/human-interface-guidelines/right-to-left , https://learn.microsoft.com/en-us/globalization/input/mirroring . Mirror directional icons; don't mirror numbers, clocks, checkmarks. Progress fills from the right. Use logical CSS properties; <bdi>/dir=auto for mixed text; test "פגישה עם Dana ב-14:30". No italics/caps in Hebrew.
